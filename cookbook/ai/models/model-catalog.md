# Model Catalog

## Overview

The model catalog is the shared model table shipped as a bundled resource
(`model-catalog.json`): one model entry per canonical model id, independent
of which gateway serves it, plus a per-(template id, spelling) offering table
for the terms (context window, output limit, token prices) that genuinely
differ between gateways. It is a **logic** component — no visual surface —
used by every provider template to answer "what do we know about this model,
and what does this gateway charge for it." Resolving a model for a template
merges the shared model facts, the matching offering, and a template's
curated model detail into one resolved model for display. The catalog is
generated by build tooling from a public catalog and committed as a bundled
resource; the shared catalog instance loads it once, falling back to an
empty (never absent) catalog if the resource is missing or unreadable.

## Behavioral Requirements

- **model-identity**: A model entry MUST be uniquely identified by its
  canonical `id`; its `aliases` list MUST list every additional spelling a
  gateway uses for that same model (e.g. `meta-llama/Llama-3.3-70B-Instruct`,
  `@cf/meta/llama-3.3-70b-instruct-fp8-fast`).
- **model-decoding-defaults**: Decoding a model entry MUST default `aliases`
  and `capabilities` to empty lists and `description` to absent when those
  keys are missing from the input payload, rather than failing to decode the
  entry.
- **offering-is-per-gateway-spelling**: An offering record MUST be looked up
  under the exact model-name spelling that one gateway (`templateID`) uses;
  the same model's terms at a different gateway, or under its canonical id,
  MUST NOT be returned.
- **offering-fields-independently-optional**: Each field of an offering
  record (`contextWindow`, `maxOutput`, `inputCostPerM`, `outputCostPerM`)
  MUST be independently representable as absent rather than defaulted to
  zero, because "unknown" and "zero" are different facts about a gateway's
  terms.
- **lookup-resolution-order**: Looking up a model by name MUST resolve it by
  exact-case match against the name index first, THEN by lowercased match
  against the same index, THEN by canonicalizing the name and matching the
  canonical-id index; the lookup MUST return no match when none of the three
  succeed.
- **canonicalization-strips-namespace**: Computing a model's canonical id
  MUST trim leading and trailing whitespace/newlines, lowercase the result,
  and drop any path segment up to and including the last `/`.
- **canonicalization-strips-free-suffix**: Computing a canonical id MUST
  strip a trailing `:free` suffix (an OpenRouter price tier, not a different
  model).
- **canonicalization-strips-quantization-suffix**: Computing a canonical id
  MUST strip at most one trailing suffix from the fixed set `-fp8-fast`,
  `-fp8`, `-fp4`, `-bf16`, `-awq`, `-int8`, `-int4`, testing them in that
  order so `-fp8-fast` matches before the shorter `-fp8` can.
- **canonicalization-preserves-other-suffixes**: Computing a canonical id
  MUST NOT strip a suffix outside the quantization set — `-turbo`,
  `-latest`, `-fast`, `-thinking` MUST survive unchanged, because they name a
  genuinely different model or alias, not a precision variant.
- **resolve-merges-three-sources**: Resolving a model for a template MUST
  merge, for one (model name, template) pair, the shared model facts (from a
  model-name lookup), the offering for that template's gateway under the
  given spelling (from an offering lookup), and the template's curated model
  detail (from an exact-id match against the template's curated entries)
  into one resolved model.
- **curated-description-wins**: Resolving a model for a template MUST use
  the curated description when it is present and non-empty, and MUST fall
  back to the shared model's description when the curated value is absent
  or an empty string.
- **curated-tools-wins**: Resolving a model for a template MUST use the
  curated tools value when present; when absent, it MUST derive the tools
  flag from whether the shared `capabilities` list contains `"tools"`,
  yielding unknown, not false, when `capabilities` is empty.
- **terms-never-curated**: Resolving a model for a template MUST take
  `contextWindow`, `maxOutput`, `inputCostPerM`, and `outputCostPerM` only
  from the resolved offering; the template's curated model detail MUST NOT
  influence any of these four fields.
- **unknown-model-resolves-empty**: Resolving a model for a template MUST
  return a resolved model (with `id` set to the requested name and marked
  empty) for a name with no matching model entry and no matching offering,
  rather than returning no result or failing.
- **shared-catalog-never-fails-to-exist**: The shared catalog instance MUST
  always yield a usable catalog: an empty catalog (`schemaVersion: 0`, no
  models, no offerings) whenever the bundled resource is missing, unreadable,
  or fails to decode.
- **load-is-total**: Loading the catalog MUST return no result — never fail
  with an error — when the given resource location has no
  `model-catalog.json` resource, when the resource's data cannot be read, or
  when the JSON fails to decode as a catalog.
- **index-built-at-init**: Constructing a catalog MUST build the name index
  and canonical-id index synchronously from the model list during
  construction, so a model-name lookup and an offering lookup are direct
  index lookups and never re-scan the model list.
- **alias-collision-last-writer-wins**: When two model entries in the model
  list share the same alias or the same `id` spelling as another entry's
  alias, the name index MUST hold whichever model appears later in the
  model list for that spelling, because index population iterates the model
  list once, in order, and later assignments overwrite earlier ones for the
  same key.
- **codable-round-trip-excludes-indexes**: Serializing and deserializing a
  catalog MUST round-trip only `schemaVersion`, `generatedAt`, `models`, and
  `offerings`; the internal name/canonical-id indexes MUST NOT appear on the
  wire and MUST be rebuilt from the model list on every deserialization.
- **value-type-is-freely-shared**: A model entry, an offering record, a
  resolved model, and the catalog itself MUST be immutable value types with
  no mutable state after construction, so one loaded catalog instance MAY be
  read concurrently from multiple threads or tasks without additional
  synchronization.
- **schema-version-not-gated**: The catalog's `schemaVersion` MUST be
  decoded and stored but MUST NOT gate loading: nothing reads or
  range-checks it, so any decodable payload loads regardless of its
  `schemaVersion`, unlike the sibling plugin-descriptor concept's own schema
  version, which is checked against a supported range and logged and skipped
  when out of range. The catalog is a resource the framework ships itself,
  generated by its own catalog-generation tooling, so a port that adds a
  range check is extending the contract, not restoring it.

## Edge Cases

- **Empty lookup name.** Looking up a model by the empty-string name — the
  name index and the canonical-id index (whose canonical form of the empty
  string is itself the empty string) both miss unless a model entry
  literally has `id == ""`; the lookup MUST return no match.
- **Sparse decode.** A JSON model object carrying only `"id"` — `aliases`
  and `capabilities` MUST decode to `[]`, `description` MUST decode to
  absent, rather than failing the whole catalog's decode.
- **Model with zero aliases.** A model entry whose `aliases == []` (e.g. the
  sample's `llama-3.3-70b-instruct`) MUST still resolve by its own `id`
  through the canonical-id index.
- **Empty catalog.** A catalog constructed with `models: []` MUST build
  empty indexes; every model-name lookup MUST return no match and every
  resolution MUST return an empty resolved model, never fail.
- **Full-size shipped catalog.** The bundled resource carries 566+ models
  across 26+ gateways; the same index-based lookup and merge logic MUST
  behave identically at that scale as in the two-model unit-test fixture —
  no size-dependent branch exists in the implementation.
- **Concurrent reads.** Model entries, offering records, resolved models,
  and the catalog itself are immutable value types built entirely during
  construction, with no mutable stored state afterward, so concurrent reads
  from multiple threads or tasks MUST be safe with no locking — this is
  applicable (the catalog is read from UI code and could be read from
  background contexts too) and is safe by construction, not merely
  untested.
- **Missing, unreadable, or malformed bundle resource.** Loading the catalog
  MUST return no result for all three (the resource cannot be located; the
  resource's data cannot be read; the JSON fails to decode), and the shared
  catalog instance MUST fall back to the empty catalog rather than crash.
- **Id/alias collision between two distinct models.** No validation exists;
  index construction's last write for a given key wins deterministically
  (see `alias-collision-last-writer-wins`), with no diagnostic distinguishing
  "intended override" from "generator bug." This is a stated fact, not a
  gap, because the resulting behavior is fully deterministic and traceable.
- **Curated model detail lookup is exact-match only.** Looking up a
  template's curated model detail matches only by exact id — no
  lowercasing, no canonicalization fallback, unlike a model-name lookup
  against the catalog. A template whose curated entry is spelled differently
  from its own models list entry SHOULD have matching spellings, or
  curation silently does not apply for that model.
- **Empty-string curated description is treated as absent.** Resolving a
  model MUST fall back to the shared model's description when the curated
  description is present but an empty string, exactly as it does when the
  curated value is absent — the two are indistinguishable to a caller of the
  resolution.
- **Canonicalization suffix ordering.** A model name ending in `-fp8-fast`
  MUST have the whole four-token suffix stripped, not just `-fp8`, because
  canonicalization checks the fixed suffix list in the order given and
  returns on the first match.
- **No network dependency (offline/disconnected: not applicable).** The
  catalog performs no network I/O of any kind — it reads only a bundled
  local JSON resource. There is no online/offline distinction for this
  component; connectivity loss elsewhere in the host app cannot affect it.

Not applicable: the catalog contains no feature-flag or remote-config check

## Analytics

Not applicable: the catalog emits no analytics events — it has no telemetry
call of any kind, success or failure.

## Privacy

Not applicable: the catalog carries no user data, credentials, or tokens —
its model and offering records are static, non-personal reference data
(model names, capabilities, pricing) shipped as a read-only bundled resource
and never written to or transmitted from the device by this component.

## Logging

Not applicable: the catalog contains no logging call of any kind. Decode and
load failures fail silently, with no diagnostic emitted — contrast the
plugin manager's warning log for an incompatible plugin descriptor, which
this component has no equivalent of (see `schema-version-not-gated` in
Behavioral Requirements).

## Platform Notes

- **SwiftUI**: The source (`packages/apple/AgenticToolkit/AIPluginKit/AIModelCatalog.swift`,
  bundled resource `model-catalog.json`, generator
  `packages/apple/AIPlugins/tools/generate_model_catalog.py`, tests
  `Tests/AIPluginKitTests/AIModelCatalogTests.swift`) has no SwiftUI
  dependency of its own — it is plain Swift, framework-agnostic. It is
  consumed today by AppKit view controllers under
  `macOS/Features/AIPlugins/Settings/` (`ModelPickerItem`,
  `ModelChooserViewController`, `ProviderPickerViewController`) purely as
  data; a SwiftUI consumer would call the same `resolve`/`model(named:)` API
  with no changes to this type. The framework's own resource-bundle lookup
  (`Bundle(for: BundleToken.self)`) needs a small anchor type — an empty
  class with no state, used solely so `Bundle(for:)` resolves to this
  framework's own bundle regardless of which app embeds it; it exists only
  because of this API's shape and has no analog outside it.
- **Compose**: Model as Kotlin `data class`es — `data class Model(val id:
  String, val aliases: List<String> = emptyList(), val description:
  String? = null, val capabilities: List<String> = emptyList())` and a
  matching `Offering`/`ResolvedModel`, giving structural equality for free
  (matching Swift's `Equatable`). `kotlinx.serialization` with `@Serializable`
  and default values on the constructor reproduces `decodeIfPresent(...) ??
  []`. Replace `byName`/`byCanonicalID` with two `Map<String, Model>` built in
  an `init {}` block, and load `model-catalog.json` as an Android asset via
  `context.assets.open(...)` wrapped in a `runCatching { }.getOrNull()` to
  mirror `load(from:)`'s total (never-throwing) contract.
- **React/Web**: `interface Model { id: string; aliases: string[]; description?:
  string; capabilities: string[] }` plus matching `Offering`/`ResolvedModel`
  interfaces. Parse with a runtime validator (e.g. zod) instead of Swift's
  throwing `Codable` initializer, applying the same empty-array/`undefined`
  defaults explicitly since `JSON.parse` performs no schema coercion. Build
  `byName`/`byCanonicalID` as two `Map<string, Model>` at module load, and
  memoize the parsed catalog in a module-level `let shared: AIModelCatalog |
  null` (lazily computed on first access) as the equivalent of Swift's
  `static let shared`.
- **AppKit / UIKit**: No AppKit- or UIKit-specific API appears in this file;
  it is genuinely UI-framework-agnostic and only consumed by the AppKit view
  controllers named above. Nothing in this type needs to change to run under
  UIKit — only the consuming views differ.
- **WinUI 3**: This is the platform this recipe exists to steer. Model
  `Model`/`Offering`/`ResolvedModel` as C# `sealed record` types — e.g.
  `public sealed record Model(string Id, IReadOnlyList<string> Aliases,
  string? Description, IReadOnlyList<string> Capabilities)` — which give
  value semantics and structural equality matching Swift's `Equatable`.
  Decode with `System.Text.Json`'s `JsonSerializer.Deserialize<AIModelCatalog>`,
  using nullable properties with constructor defaults (or a custom
  `JsonConverter`) to reproduce `decodeIfPresent(...) ?? []`. Build
  `byName`/`byCanonicalID` as two `Dictionary<string, Model>` populated once
  in the record's constructor, exactly mirroring the Swift index-build loop
  (including last-writer-wins on a colliding key). Ship `model-catalog.json`
  as Content in the app package and load it via
  `Windows.ApplicationModel.Package.Current.InstalledLocation` (or an
  embedded-resource stream) instead of `Bundle.url(forResource:)`. Expose the
  loaded value through a `Lazy<AIModelCatalog>` (the `Lazy<T>` equivalent of
  Swift's `static let shared`), wrapping the file read and
  `JsonSerializer.Deserialize` call in a `try`/`catch` that falls back to an
  empty `AIModelCatalog` on any exception, matching `load(from:)`'s
  never-throw, empty-on-failure contract. `async`/`Task`-based file I/O is
  optional here since the resource is local and small; a synchronous read at
  startup is the direct port of the Swift `Bundle`/`Data(contentsOf:)` call.

## Design Decisions

- **Decision**: Split shared, per-model facts (`Model`: description,
  capabilities) from per-offering, per-gateway terms (`Offering`: context
  window, output limit, prices), keyed by `templateId` and the gateway's own
  spelling of the model.
  **Rationale**: The same model (e.g. `gpt-oss-120b`) is served by many
  gateways; describing it inside every provider's descriptor would copy one
  blurb dozens of times and let the copies drift, while a model's context
  window and token prices genuinely differ per gateway (one number would be
  wrong nearly everywhere) — both facts are stated directly in the source's
  top-of-file documentation comment.
  **Approved**: pending
- **Decision**: `AIModelCatalog.shared` never fails to exist — a missing,
  unreadable, or malformed `model-catalog.json` yields an empty catalog
  rather than a crash or a thrown error surfacing to the caller.
  **Rationale**: per the source comment on `shared`, "a stale or absent
  catalog costs descriptions, and must never take the provider UI down with
  it" — losing model descriptions is an acceptable degradation; losing the
  entire provider picker is not.
  **Approved**: pending
- **Decision**: Curated `ModelDetail` overrides only the descriptive fields
  (`description`, `tools`, `goodFor`) in `resolve(...)`, never the numeric
  `Offering` terms.
  **Rationale**: per the source comment on `resolve`, curated fields are
  "hand-written for the few flagship models where the generated blurb isn't
  good enough, and a regeneration must never silently overwrite that
  judgement" — but a gateway's context window and prices are facts the
  gateway itself reports, which curated prose has no authority to change.
  **Approved**: pending
- **Decision**: `canonicalID(_:)` strips only a fixed, explicit set of
  quantization/precision suffixes (checked longest-first), and leaves every
  other trailing token — `-turbo`, `-latest`, `-fast`, `-thinking` — alone.
  **Rationale**: `generate_model_catalog.py`'s sibling `canonical_model_id`
  (which this Swift function must mirror per its own doc comment) states
  these suffixes are "the same weights served at lower precision" and safe to
  fold onto the base model, while `-turbo`/`-fast`/`-latest`/`-thinking`
  "name genuinely different models or aliases" and must never be folded.
  **Approved**: pending
- **Decision**: `AIModelCatalog.schemaVersion` is carried on the wire and
  stored, but — unlike `AIPluginDescriptor.schemaVersion` — is never gated
  against a known-compatible range before the catalog is used.
  **Rationale**: no comment in `AIModelCatalog.swift`,
  `generate_model_catalog.py`, or the shipped catalog explains this
  asymmetry; the recipe records the behavior as it is
  (`schema-version-not-gated`): the framework ships and regenerates its own
  catalog, so there is no foreign payload to guard against today.
  **Approved**: pending

Notes: graceful-degradation passes because `load(from:)`/`shared` always

swallowed via `try?` with no diagnostic signal, unlike the sibling
`AIPluginManager` warning log for an incompatible plugin. data-integrity is
partial because `id`/alias collisions across `Model` entries silently
overwrite in the index with no validation (see
`alias-collision-last-writer-wins`). no-hardcoded-strings fails because
`Model.description` and curated `ModelDetail.goodFor` ship as English-only
prose with no localization mechanism (see Localization).
